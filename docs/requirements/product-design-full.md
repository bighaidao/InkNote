## 第一章：产品本质的重新定义

你的三份文档合并起来，实际上在说同一件事：

> **InkNote 的竞争优势不是"Markdown 编辑器"，而是一个让程序员和知识工作者把 `.md` 文件仓库作为真正工作站使用的本地运行时。**

现有产品的问题不是功能少，而是**三个错位**：

| 错位 | 现状 | 应有逻辑 |
|---|---|---|
| 身份错位 | 文件只是打开源，用完即关 | 文件是工作区的持久居民，有状态、有历史、有关联 |
| 格式错位 | `.md` 是主角，其他格式是异类 | `.md` 是输出层，代码/图片/文档/数据是一等输入源 |
| 行为错位 | 打开文件就是编辑，关闭就是结束 | 打开文件是进入一个上下文会话，关闭不销毁会话记忆 |

## 第三章：产品逻辑体系重建

### 3.1 核心模型：「会话型工作台」而非「文件查看器」

用户打开 InkNote 的动机不是"看一个文件"，而是"进入一个持续的工作上下文"。
这意味着产品的核心应该围绕**会话**而不是**文件**设计。

```
【当前模型（文件中心）】           【目标模型（会话中心）】

打开文件 → Tab → 关闭              打开工作区 → 进入会话
     ↑                                    ↓
   文件树                          会话有记忆（Tab 布局/滚动位置/侧栏状态）
                                   会话有历史（最近文件/最近操作）
                                   会话有关联（谁引用了谁）
                                   会话可持久（重启恢复）
```

你的多窗口方案（B1）已经在往这个方向走——每个窗口是独立会话，有自己的工作区、Tab 集、侧栏状态。**Phase 1 的多格式预览是这个会话模型的扩展，而不是一个孤立的新功能。**

### 3.2 文件二元公民制（从产品逻辑落地，而非格式列表）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        InkNote 文件公民等级制度                              │
├────────────────────┬───────────────────────────────────────────────────────┤
│                    │                                                       │
│  一等公民：资产文件   │  二等公民：参考文件                                    │
│  格式：.md          │  格式：代码、图片、PDF、Office、压缩包、数据文件         │
│                    │                                                       │
│  权利：             │  权利：                                               │
│  · 可读写           │  · 可只读预览（沙箱隔离）                               │
│  · 进全局搜索       │  · 文本类进全局搜索                                    │
│  · 有 dirty 状态    │  · 进文件名快速打开                                    │
│  · 有保存历史       │  · 外部修改后静默刷新（无冲突提示）                      │
│  · 有编辑模式切换   │  · 有文件元信息展示（大小/编码/类型）                    │
│                    │                                                       │
│  义务：             │  义务：                                               │
│  · 关闭前确认 dirty │  · 关闭不提示（无 dirty 态）                           │
│  · 保存时写盘       │  · 不可覆盖磁盘                                        │
└────────────────────┴───────────────────────────────────────────────────────┘
```

**这个二元制的产品价值**：用户不需要记住"这个文件能不能编辑"，Tab 的角标（只读徽标）、菜单项的可用性（保存/导出置灰）、右键菜单的选项差异，全部自动推导。

### 3.3 Tab 体系的完整行为定义

当前代码实现的 Tab 行为有几个隐形缺口，Phase 1 引入 Preview Tab 后会放大：

## 第四章：六大功能模块完整设计

### 模块一：多格式预览（Phase 1 核心）

#### 1.1 预览引擎分级策略

不是所有格式都需要重型 WASM——按渲染成本分三档：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 轻量级（零依赖，原生渲染）                                                     │
│  格式：png jpg jpeg gif webp svg bmp ico avif                                 │
│  方案：convertFileSrc → native <img>，不走 open-file-viewer                   │
│  交互：滚轮缩放 / 双击 1:1 / 拖拽平移 / 状态栏显示分辨率                       │
│  上限：100MB（实测 8K 图 ~30MB，100MB 是安全上限）                             │
├──────────────────────────────────────────────────────────────────────────────┤
│ 中量级（CM6 只读，复用已有依赖）                                                │
│  格式：所有 searchableTextExtensions 中的代码/文本格式                         │
│  方案：CodeMirror 6 只读模式 + legacy-modes 语法高亮（已有依赖，零增量）        │
│  交互：行号 / 滚动 / 选中复制 / Cmd+F 查找（CM6 内置 search panel）            │
│  上限：10MB（超出降级为纯文本无高亮 + 性能保护横幅）                            │
├──────────────────────────────────────────────────────────────────────────────┤
│ 重量级（@open-file-viewer/react WASM，按需懒加载）                             │
│  格式：PDF / Word / Excel / PPT / ZIP / EML                                   │
│  方案：首次打开时动态 import，后续 WASM 已缓存                                  │
│  交互：各插件自带（PDF 翻页/缩放/搜索，Office 滚动，ZIP 目录树展开）            │
│  上限：PDF/Office 200MB，ZIP 500MB（仅列目录不解压内容）                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

#### 1.2 代码文件预览的差异化价值

代码文件的预览不只是"高亮显示"，它是 InkNote 定位"开发伴侣"的核心体现：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  📄 config.yaml  [只读]                         [在默认编辑器打开] [复制路径] │
├──────────────────────────────────────────────────────────────────────────────┤
│  1  database:                                                                │
│  2    host: localhost                                                        │
│  3    port: 5432                        ← 行号（CM6 自带，一行配置）          │
│  4    name: inknote_prod                                                     │
│                                                                              │
│ ─────────────────────────────────────────────────────────────────────────── │
│ YAML · UTF-8 · 2.1 KB · 最后修改 2026-09-24 11:30                           │
└──────────────────────────────────────────────────────────────────────────────┘
```

状态栏的文件元信息（格式/编码/大小/修改时间）是从 `stat_file` + `read_binary_file` 的结果中直接提取，不额外读盘。

#### 1.3 ZIP/压缩包预览的产品逻辑

压缩包的预览有一个非常特殊的用户场景：**用户想知道这个包里有什么，而不是要解压它**。所以预览的终点是"目录树 + 大小统计"，而不是"打开内部文件"。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  📦 release-v2.0.zip  [只读]  38.4 MB                   [在访达中显示]       │
├──────────────────────────────────────────────────────────────────────────────┤
│  ▾ release-v2.0/                              3 文件夹   12 文件   38.4 MB   │
│    ▾ bin/                                                                    │
│      📄 inknote         22.1 MB                                              │
│      📄 inknote.sig       1 KB                                               │
│    ▾ docs/                                                                   │
│      📄 CHANGELOG.md    48 KB                                                │
│      📄 README.md       12 KB                                                │
│    📄 install.sh         8 KB                                                │
│                                                                              │
│  ─────────────────────────────────────────────────────────────────────────  │
│  ZIP · 12 个文件 · 3 个目录 · 38.4 MB（解压后约 82.1 MB）                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

**不实现**：点击压缩包内文件直接预览——这条路的工程代价极高（需要流式解压），产品收益不大，且 macOS 自带 Archive Utility 已经能做。

### 模块二：全局搜索的进化

#### 2.1 当前状态（代码事实）

`search_workspace` 已经在 Rust 侧实现，`searchableExtensions.json` 已包含 40+ 文本格式，白名单双端共享（前端 import 同一 JSON 文件，Rust `include_str!` 编译期读入）。

**这是你设计里最漂亮的一个决策**——扩展名白名单的单一来源消除了前后端漂移的整个问题类别。

#### 2.2 搜索结果的类型感知跳转

搜索结果点击跳转目前只有一种行为（打开 md 文件跳到对应行）。Phase 1 后需要分类处理：

```
搜索结果点击
     │
     ▼
  文件扩展名判断
     │
  ┌──┴────────────────────────────┐
  │                               │
  ▼                               ▼
.md / .markdown                代码/文本文件
  │                               │
  ▼                               ▼
现有逻辑：                  Preview Tab（只读 CM6）
打开编辑器                  滚动到命中行（通过 CM6 scrollIntoView）
跳到指定行                  高亮匹配段
```

**技术要点**：Preview Tab 打开时带 `initialLine` 参数，CM6 只读实例在挂载后执行一次 `scrollIntoView`，不涉及 cursor。

#### 2.3 快速打开（Cmd+P）的扩展

当前 Quick Open 只枚举 `.md` 文件（需确认）。Phase 1 后，`list_workspace_files` 已返回全部 `previewableExtensions`，Quick Open 的文件列表自然扩展——**零额外工作**，因为后端已经做了。

### 模块三：侧栏体系（顶通布局 + 多会话感）

这是 mac-native 文档中优先级最高的视觉项（C2，侧栏顶通布局），也是用户说"缺少点什么"的最大来源。

#### 3.1 顶通布局的最终形态

```
│    ▾ docs        │ # API 接口规范 v2.0                                       │

│      📄 er.pdf   │ 认证方式采用 Bearer Token，具体字段定义                   │
```

**文件树图标的格式感知**：文件树节点的图标不应该都是 `📄`，需要按格式类别显示不同图标。这是"参考文件是一等居民"的最直观体现。

```

.sql → 🗃️（数据库类）
```

### 模块四：文件操作的互联能力

这是从"文件查看器"向"工作台"跃迁的关键——让文件能**主动参与**写作流程，而不是被动等待打开。

#### 4.1 拖拽到编辑器：智能插入

**现状**：外部文件拖入窗口是打开文件（`App.tsx:1373`）。  
**扩展**：当拖入目标是**编辑器区域**且当前 Tab 是 Document Tab 时，触发不同行为：

```
用户从文件树拖拽文件到编辑器正文
           │
           ▼
      文件类型判断
           │
  ┌────────┴──────────────────────────────┐
  │                                       │
  ▼                                       ▼
  图片格式                           非图片格式
  │                                       │
  ▼                                       ▼
自动复制到当前 md 同级                弹出气泡菜单：
assets/ 目录（如有）                  ○ 插入为相对链接  → [文件名](./path/file.ext)
计算相对路径                          ○ 插入文件名       → `file.ext`
插入 ![文件名](./assets/xxx.png)      ○ 取消
```

这个功能**现有拖放入口已存在**（`App.tsx:1373` 的 `handleDroppedFiles`），只需在判断目标区域时分叉路径。

#### 4.2 文件右键菜单的完整设计

文件树右键菜单要区分 Document/Preview 两类文件，且要面向"开发伴侣"场景补充操作：

```
.md 文件右键                         非 md 文件右键

在 InkNote 中打开           ✓        在 InkNote 中预览           ✓
在新窗口打开               ✓        用系统应用打开              ✓
─────────────────                   ─────────────────────────────
重命名                     ✓        重命名                       ✓
复制                       ✓        复制                         ✓
移动到...                  ✓        移动到...                    ✓
删除                       ✓        删除                         ✓
─────────────────                   ─────────────────────────────
复制相对路径               ✓        复制相对路径                  ✓
复制 Markdown 链接         ✓        复制 Markdown 引用            ✓
  → `[文件名](./path.md)`              (图片：`![alt](./path.png)`)
                                      (文档：`[文件名](./path.pdf)`)
在访达中显示               ✓        在访达中显示                  ✓
```

**「复制 Markdown 引用」** 是开发者的高频操作：在写文档时经常需要引用同目录的架构图、数据文件、配置文件，手写相对路径容易出错，一键复制格式化的引用语法是真实痛点。

## 第五章：产品体验护栏（必须守住的底线）

### 5.1 性能护栏（来自 resource-consumption-assessment.md）

| 指标 | 上限 | 守护方式 |
|---|---|---|
| 冷启动到可输入 | < 1.5s | 预览引擎懒加载（md-only 会话零负担） |
| 全库搜索（有索引，10k 文件） | < 300ms | Rust 侧已实现，只返回命中行 |
| 预览引擎首次加载（含 WASM） | < 800ms | 首次打开 Preview Tab 时才触发 |
| 常驻内存（10 个 Tab） | < 400MB | Blob LRU 5 条上限 + viewer.destroy() |
| 单个 Preview Tab 内存 | < 100MB | 大文件护栏在 Rust `read_binary_file` 侧 |

### 5.2 安全护栏（CSP 最小放开原则）

仅在现有 CSP 基础上新增 3 个指令，不放开其他任何约束：
- `script-src` 加 `wasm-unsafe-eval`（WASM 必须）
- 新增 `worker-src 'self' blob:`（Worker 必须）
- `connect-src` 加 `blob: data:`（Worker 内部 fetch WASM 必须）

### 5.3 用户预期护栏（不能让用户产生误解）

| 容易误解的点 | 必须明示的方式 |
|---|---|
| PPT 预览保真度有限 | Tab 标题旁显示小提示"预览以排版为主，动画效果不支持" |
| 代码文件只读，不可编辑 | Tab 右上角只读徽标 + 菜单项保存置灰 |
| ZIP 预览只列目录，不解压 | 工具栏显示"目录预览模式" |
| 大文件超限后的系统打开 | 说明"已用系统应用打开，Tab 可安全关闭" |

## 第七章：这版设计和之前的本质区别

| 维度 | 之前的设计 | 这版设计 |
|---|---|---|
| 出发点 | 从格式列表出发（"支持哪些格式"） | 从用户工作流出发（"用户在做什么，需要什么"） |
| 深度 | 停留在"多格式查看器"的功能描述 | 落到 Tab 行为矩阵、文件路由决策树、代码级约束 |
| 边界 | 提出了很多"借鉴"功能（Quick Look / 反向引用） | 只保留工程代价合理的，并说明现有代码哪里可以复用 |
| 痛点 | 泛化痛点 | 具体痛点（排除目录、搜索跳转感知、Tab 行为差异） |
| 与现有文档的关系 | 独立于现有文档 | 是 roadmap + mac-native + file-preview 三者的完整整合与具体化 |
