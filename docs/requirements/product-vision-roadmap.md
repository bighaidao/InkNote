# InkNote 产品定位与整体路线图

> 状态：规划稿（Phase 1 已确认方案，Phase 2+ 待逐项立项确认）
> 日期：2026-09

## 1. 产品定位重塑

### 1.1 从「Markdown 编辑器」到「本地优先的知识工作台」

| | 现有定位 | 目标定位 |
| --- | --- | --- |
| 一句话 | 像写普通文档一样写 Markdown | 本地优先的高性能 Markdown 知识工作台：写作、知识管理与项目开发共处一室 |
| 对标 | Typora | Obsidian 的知识管理 + Typora 的写作体验 + 轻量的开发伴侣能力 |
| 文件观 | 只有 .md 是一等公民 | .md 是核心资产；代码、图片、Office、PDF、HTML 是项目里的合法居民，可高性能预览 |

### 1.2 差异化坐标

- **Obsidian**：知识管理极强（双链/图谱/插件生态），但闭源格式生态、编辑体验一般、代码支持弱。
- **Typora**：写作体验优雅，但单文件视角、无工作台、无知识层。
- **VSCode**：开发无敌，但写作排版体验几乎为零。
- **InkNote 的空位**：以「标准 .md 文件 + 所见即所得」为地基，向上长出工作台级能力——多格式预览让一个笔记仓库可以同时是项目文档库，而不需要用户在三个工具间切换。

## 2. 能力矩阵（现状盘点）

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| Markdown 所见即所得编辑 | ✅ 已有 | CodeMirror 6 + 自研 live preview |
| 多窗口/多工作区/文件树 | ✅ 已有 | 独立监听器、重启恢复 |
| 全局搜索（内容+文件名） | ✅ 已有 | Rust 侧实现，仅扫 .md/.markdown |
| 导出 HTML/PDF | ✅ 已有 | macOS/Windows 支持 PDF |
| 代码/文本文件预览 | 🆕 Phase 1 | CM6 只读 + legacy-modes 高亮 |
| 图片预览 | 🆕 Phase 1 | 原生 img + convertFileSrc |
| Office/PDF/HTML/压缩包预览 | 🆕 Phase 1 | @open-file-viewer/react（MIT），插件按需注册 |
| 搜索收录文本类文件 | 🆕 Phase 1 | 与预览同步扩展白名单 |
| 性能专项（索引/虚拟化/懒加载） | 📋 Phase 2 | 见 §4 |
| 双链/标签/反向链接/图谱 | 📋 候选 | Obsidian 核心能力，需单独立项评估 |
| Git 集成/片段/模板 | 📋 候选 | 项目开发伴侣方向的延伸，需单独立项 |

> Phase 1 范围已在对话中确认：全格式一次做齐（PPTX 接受 pptx-preview 系的保真度限制），搜索同步扩展文本类格式。

## 3. Phase 1 技术方案（已确认，摘要）

- **选型**：`@open-file-viewer/react`（MIT，1.8k star，插件化架构），fallback 备选 `@file-viewer/react`（协议含 AGPL 组件，非首选）。
- **架构**：Tab 增加 `kind: "document" | "preview"`；Rust 新增 `read_binary_file`；新组件 `FilePreviewTab` 统一承接非 md 文件；md 编辑链路零改动。
- **插件注册**：textPlugin / officePlugin / pdfPlugin / archivePlugin / emailPlugin 按需裁剪。
- **关键风险**：Tauri CSP 需放开 `blob:` `worker-src` `wasm-unsafe-eval`；WASM/字体资产自托管进 `public/`；大文件上限防护（建议 100–200MB，超限降级「系统应用打开」）。
- 详细实现方案见后续 `docs/architecture/file-preview.md`（实施时产出）。

## 4. 性能策略（Phase 2 专项）

### 4.1 分层性能设计

```
启动性能          渲染性能            检索性能            内存性能
─────────        ─────────          ─────────          ─────────
首包代码分割      CM6 增量解析(已有)   Rust 全量扫描(现状)  viewer.destroy()
重库 import()     预览引擎懒加载      → mtime+size 增量   Blob URL revoke
窗口按需恢复      PDF 分页懒渲染      → 后台索引线程      WASM 用毕可卸
设置延迟初始化    文件树/大纲/搜索     文件名索引常驻      Tab LRU 上限
                  结果虚拟滚动        大小上限防护        图片解码缓存上限
```

### 4.2 量化目标（验收口径）

| 指标 | 目标 | 现状口径 |
| --- | --- | --- |
| 冷启动到可输入 | < 1.5s（M 系列 Mac） | 待建立基线测量 |
| 10k 文件全库搜索（有索引） | < 300ms | 现为全量扫描，随文件数线性 |
| 预览引擎首次加载 | < 800ms（含 WASM） | 新增项 |
| 常驻内存（10 Tab） | < 400MB | 待建立基线测量 |

> 先在 Phase 1 顺带建立基线测量脚本（启动耗时、搜索耗时、内存），Phase 2 用数据驱动优化，避免凭感觉调优。

### 4.3 配置化性能项（支柱「可配置可优化」的落地）

- 预览：启用哪些格式插件、大文件阈值、PDF 渲染质量（DPI）。
- 搜索：内容索引开关、索引重建、排除目录（.gitignore 感知为候选）。
- 编辑器：虚拟滚动阈值、大文档保护线。

原则：**默认即最优，高级项可调**，不把调优负担丢给普通用户。

## 7. 风险与门禁

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| open-file-viewer 上游停维护 | 中 | MIT 可 fork；API 集中在 FilePreviewTab 单组件，可换 file-viewer |
| CSP 放开引入安全面 | 中 | 仅放开 blob/worker/wasm-unsafe-eval，维持其他约束；预览内容仍隔离在容器内 |
| PPTX 保真度不足 | 低 | 文案明示「预览以排版为准，复杂动画不支持」 |
| Phase 2+ 范围膨胀 | 高 | 严格逐项立项确认，本文件不构成 Phase 2+ 的开工授权 |

- 门禁 1（产品）：Phase 1 交互态（空/加载/异常/极端数据四态）实施前再走一次确认。
- 门禁 2（架构）：`docs/architecture/file-preview.md` 产出并确认后方可编码。
