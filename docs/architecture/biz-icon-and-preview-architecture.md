## 2. 方案推演反敷衍协议（决策对比）

### 2.1 文件图标方案推演

| 考量维度 | 方案 A（主推：VS Code / PyCharm 经典 IDE 级矢量子集） | 方案 B（沿用 Emoji / 卡通表情） | 方案 C（引入全量三方庞大 NPM 包） |
| :--- | :--- | :--- | :--- |
| **最大获益点** | **高度对齐开发者视觉习惯**（TS 蓝底白字、Python 蓝黄双蛇、Rust 齿轮、Word 蓝 W 等），极简轻量（<25KB），瞬间拥有专业 IDE 质感。 | 零开发，开箱即用。 | 图标库大而全（数千枚）。 |
| **不可承受代价** | 需对齐并维护一份核心 30+ 种主流格式的精确 SVG path 字典。 | **视觉像玩具/表情包，用户明确吐槽“丑/不习惯”**。 | **导致打包体积剧增数百 KB**，启动变慢，违反轻量哲学。 |
| **选型结论** | **采纳方案 A**：最契合用户审美与习惯，最具生产力质感。 | 坚决推翻并废弃。 | 放弃（过度设计）。 |

### 2.2 Word / PPT / Excel / PDF 文本复制实现推演

| 考量维度 | 方案 A（主推：DOM 选区划选 + 原生 Extractor 纯文本秒级抽取） | 方案 B（仅支持鼠标划选复制，不支持全文提取） | 方案 C（调用 Rust 后端依赖重型解析库） |
| :--- | :--- | :--- | :--- |
| **最大获益点** | **100% 满足用户强需求**：既能随选随拷，又有一键全篇文本秒提；完全在前端轻量化异步完成，零 Rust 编译依赖负担。 | 实现最轻。 | 提取底层能力理论上最深。 |
| **不可承受代价** | 对非规范格式需做优雅降级（如纯图片扫描件提示）。 | **无法满足用户整篇讲义/文档快速抽取的强诉求**。 | **导致 Rust 二进制膨胀数十 MB**，且跨平台交叉编译极其脆弱。 |
| **选型结论** | **采纳方案 A**：最优雅、响应最快，用户体验最完整。 | 放弃（无法满足用户核心强需求）。 | 放弃（体积严重膨胀）。 |

## 3. 架构五维审查清单

1. **状态归属**：
   - 提取的纯文本不存入全局状态树，直接瞬时写入系统剪贴板（Clipboard），保证内存 0 滞留；
   - 图标映射为纯函数映射，无异步状态竞争与多副本漂移风险。
2. **生命周期**：
   - 文本提取全部封装为 cancellable Promise，若用户在提取中关闭 Tab，立即终止，不泄漏计算资源；
   - 右键菜单具备 pointerdown 外部点击自动注销、Escape 键快速注销机制。
3. **异步时序**：
   - 复制操作通过 `@tauri-apps/plugin-clipboard-manager` 或浏览器 Clipboard API 双通道保险写入，确保跨平台剪贴板稳定性。
4. **爆炸半径**：
   - 仅增量改造 `src/preview/` 与 `src/components/FileTree.tsx`；
   - 核心 Markdown 编辑链路（`editor.ts` 等）零侵入、零改动。
5. **单双向门决策**：
   - **双向门**：纯前端表现与剪贴板能力扩展，无数据库 Schema 变更，随时可回退与升级。
